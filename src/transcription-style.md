# 转录与排版规范

本文档是本项目编辑、校对和 AI 辅助修改时的工作规范。它记录本书已经采用的排版习惯，以及哪些格式不能在没有依据的情况下被自动统一。

## 总原则

- 扫描原书和已确认的人工修订优先于一般的 Markdown、LaTeX 或中文排版习惯。
- 不因“看起来更规范”而批量改写全书；格式修改必须有扫描原图、上下文、构建结果或明确的项目决定作为依据。
- 无法确认的内容保留原样，并在验证记录中列为待确认项。
- 只修正能够确认的 OCR、排印、转义或渲染错误；不借格式修正之名改变技术含义。
- 合并稿是 mdBook 的正式阅读版本，`source-sections/` 是分节编辑材料。修改一处时，应检查另一处是否需要同步。

## 数学与上下标

- 数学格式沿用当前文件和章节已经使用的 MathJax 定界符，不为了统一视觉而任意更换等价写法。
- 变量、器件编号、上下标和单位是否包裹在行内数学中，应结合原书排版、所在句子的语义和同一章节的既有习惯判断。
- 不自动把所有 `VCC`、`RL`、`Q1` 或型号名称转换成数学格式；SPICE 网表、器件型号、表格字段和原图文字可能需要保持原样。
- 默认不把解释性文字放入数学环境，也不把原本属于公式的内容移出数学环境；已确认的原书版式特例见下文。
- 公式中的中文说明应使用项目已经采用的可渲染写法；不得留下未经验证的裸文本、损坏的定界符或无意义的转义。
- 公式编号、图号、表号和原书上下标属于内容的一部分，不能因排版重写而丢失。

## 已确认的特殊例外

- **公式内注释：**式（1.23）以及附录 A 的式（A.10）、式（A.11）延用原书版式。中文注释直接保留在显示公式环境中，并保留公式行末的四个反斜线；渲染后注释应紧接在公式正下方，不另起普通正文段落。不要仅为“语法整洁”把这些注释移到公式外。
- **标题中的行内公式：**第 2 章标题中的变量必须使用双反斜线定界符，例如 \\(h_{fe}\\) 和 \\(f_T\\)。这是当前 Markdown/MathJax 转写链的既定写法，不得改成单反斜线形式。
- **SPICE 参数说明中的 HTML 上下标：**第 3 章 SPICE 模型参数说明保留 <sub>、<sup> 写法，例如 I<sub>S</sub> 和 10<sup>−14</sup>。这是为了保持与正文相同的字号；改用数学环境会使这类短参数说明显得过大。

## 表格与图注

- 能够逐项核对的表格可以转为 Markdown；复杂跨栏表格或无法可靠识别的内容继续保留扫描图。
- 表格中的型号、SPICE 参数名、引脚名和单位栏不应仅为追求数学化而改写。
- 图像文件名、图片链接、图号和图注必须相互对应；图注可检索，但不应改变原图中的技术标注。
- 修改图片引用前，先确认实际文件名，并在修改后执行活动图片链接检查。

## SPICE 与程序

- 网表和程序放在代码块中，保持原始字符、大小写、节点名和元件标号。
- 为使代码可运行而进行的技术性修正，必须在正文或邻近注释中说明，并保留扫描原件供对照。
- 不把代码块中的 `Q1`、`R1`、`VCC` 等标记当作普通正文变量进行格式化。

## 引用、脚注与结构

- 保留原书章节号、公式号、图号、表号、照片号、List 编号和脚注关系。
- 引用上标、脚注和正文数学上下标是不同问题，不能混用处理。
- 专栏沿用引用块样式；验证记录不进入 `SUMMARY.md` 的正式阅读目录。

## 修改流程

每次涉及排版或公式的修改，至少应：

1. 对照扫描页和相邻上下文，确认修改对象及修改理由；
2. 同时检查合并稿与对应的分节源文件；
3. 运行 `mdbook build`；
4. 运行 `git diff --check`；
5. 对图片链接、损坏字符和公式渲染做针对性检查；
6. 在 `src/verification.md` 或对应章节验证记录中留下可追溯说明。

## 中文专业术语

本书原本用日语撰写，翻译为中文出版时部分专业用语采用日语直译，这部分内容一律修正为中文专业用语

1. “型名” 修正为 “型号”
2. 傅里叶变换相关的“基本波”表述修正为“基波”
3. 与运放封装相关的“两电路”表述修正为“双运放”， “单运放”。
4. “电压保证” 修正为 “稳压”

如果本规范与用户对某一处的明确要求冲突，以用户要求为准，并在后续修订中更新本规范。
